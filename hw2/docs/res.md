## 7. Выявленные дефекты

### 7.1. Некорректный подсчет весов модели

При первичном запуске inspect получаем `2 031 739 904` параметров, что существенно выше заявленных 1.7B (приблизительно на 18% больше). Проблема возникает в методе

```py
def parameter_rows(model) -> list[dict]
```

Связано это с тем, что у Qwen embed_tokens и lm_head - это один и тот же тензор параметров. Следовательно, для корректного подсчета необходимо дополнительно проверять посчитанные параметры. В итоге должно получиться, что lm_head не имеет собственных параметров.

Для этого введем множество уже посчитанных весов и проверять вхождени при каждом новом прибавлении.

В итоге получаем уже более корректное значение `1 720 574 976`.

### 7.2. Проблема накопления хуков

`register_forward_hook()` возвращает `RemovableHandle`, но в методе `forward_hooks()` эта возможность теряется. Поэтому после каждого вызова `activation_norms()` хуки остаются висеть на слоях.

В результате повторный запуск:

```py
activation_norms(...)
activation_norms(...)
```

оставляет уже несколько хуков на одних и тех же слоях. Это увеличивает расход памяти и меняет состояние объекта модели.

для исключения этой проблемы `forward_hooks()` возвращает сприсок `handles`, которые затем несложно удаляются:
```py
try:
    with torch.inference_mode():
        model(**inputs)
finally:
    for handler in handlers:
        handler.remove()
```

### 7.3. Замер памяти на некорректном устройстве

При первичном замере памяти на всех трех устройствах результат составлял около 4470 Мб, что связано с замером на некорректном устройстве.

Вес модели в bf16 - 3282 МБ. В Full fine-tune добавляются градиенты и два состояния AdamW, поэтому расход увеличивается примерно в 4 раза: 4382 → 17004 МБ. В LoRA обучается только 1,6 млн параметров, поэтому расход составляет 5684 МБ.

ru_maxrss измеряет RSS процесса, а не память MPS-аллокатора, поэтому почти не меняется (4471–4472 МБ).

```py
def device_allocated_bytes(device: torch.device) -> int:
    """Сколько памяти занято прямо сейчас."""
    if device.type == "mps":
        return int(torch.mps.driver_allocated_memory())
    if device.type == "cuda":
        return int(torch.cuda.memory_allocated(device))
    used, _ = peak_rss()
    return used
```

### 7.4. Некорректная методика замера памяти

Вместе с предыдущим дефектов влиял на результаты замеров памяти. Заключался в некорректной методике замера, а именно снятии значения загрузки в конце процесса, а не как пикового за весь процесс. Для получения корректных значений необходимо отредактировать класс `PeakMemory`

```py
        if self.device.type == "cuda":
            torch.cuda.synchronize(self.device)
            self.used = int(torch.cuda.max_memory_allocated(self.device))
        elif self.device.type == "mps":
            torch.mps.synchronize()
            self.used = max(self.used, device_allocated_bytes(self.device))
            self._stop.set()
            if self._sampler is not None:
                self._sampler.join()
```
