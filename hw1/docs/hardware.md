## Ход работы

### Исправление дефектов

#### Дефект № 1
Перед первичным запуском, был изучен файл `pyproject.toml`, содержащий зависимости проекта. Однако зависимости были представлены списком без указания требуемых версий:

```toml
dependencies = [
    "torch",
    "transformers",
    "accelerate",
    "numpy",
    "pyyaml",
]
```

Такой подход к описанию требуемого окружения потенциально может привести к проблемам при запуске из-за несогласованности версий зависимостей на разных машиных. Для превентивного исключения таких проблем, версии всех зависимостей, а также версия `Python` были зафиксированы. В таком случае поведение проекта на новой машине будет детерменировано.

Итоговый `pyproject.toml`:
```toml
[project]
name = "mlops-hw1"
version = "0.1.0"
description = "MLOPS-26, домашняя работа 1: окружение и бенчмарк"
requires-python = "==3.12.14"
dependencies = [
    "torch==2.14.0",
    "transformers==5.16.1",
    "accelerate==1.14.0",
    "numpy==2.5.3",
    "pyyaml==6.0.3",
]

[tool.uv.workspace]
members = [
    "mlops-course",
]
```

#### Дефект № 2

Следующая возникщая проблема - некорректное использование `params.yaml`. Часть параметров, в том числе имя модели из параметров не использовались. То есть изменение имени моделеи в параметрах не влияло на инференс и бенчмарк. Для решения этой проблемы потребовалось найти все места, где имя модели было указано прямо в коде:
- `model.py` -> `load_model()` - место загрузки модели;
- `bench.py` -> `main()` - для вывода результатов бенчмарка;
- `generate.py` -> `main.py` - для вывода информации о модели.

#### Дефект № 3

В файле `bench.py` представлена логика замера параметра `tokens/sec` при инференсе модели, однако изначально длина ответа почти не влияла на этот параметр. Дефект заключался в том, что отрезок времени замера включал в себя загрузку весов модели, что является критичным недостатком, т.к. время загрузки ~5 Gb весов в несколько раз выше, чем время генерации. В результате цифры занижены и нерепрезентативны.

Для достоверного замера логика была организована следующим образом:

1. Первый отрезок - загрузка параметров модели. Этот параметр вычисляется отдельно и не участвует в подсчете следующих критериев
2. Выполняется прогревочный прогон (или несколько - зависит от `params.yaml`). Он необходим для загрузки модели в память, т.к. в первый раз это влияет за скорость генерации. Время пргревочного прогона не измеряется и не участвует в дальнейших вычислениях.
3. На каждом "реальном" прогоне таймер начинает отсчет непосредственно перед генерацией, и завершает сразу после её окончания.

В итоге показатель `tokens_per_sec` возрос в несколько раз и нормализовался. Итоговые значения колеблются в диапазоне от 43.94 до 44.14.

#### Дефект № 4

При инференсе модели результат генерации отличался от запуска к запуску. Это связано с двумя критическими просчетами в коде. Во-первых, "температура" составляет 0.7, что не соответсвует требованию детерминированности запуска. Для достижения этого требования необходимо установить значение равное 0. Во-вторых, хоть проект и содержит функцию `set_seed` для фиксации зерна случайности, она не используется при инференсе (`generate.py`) и замере (`bench.py`). Эти недостатки были исправлены.
