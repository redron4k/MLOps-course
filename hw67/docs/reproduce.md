# Воспроизведение и сдача

Команды выполняются из `practice/hw67`. Основной порядок сохранён в README и EVALUATION.
Окружение закреплено `.python-version` (3.12) и `uv.lock`; базовая модель — точный commit в `params.yaml`.

## Данные

`data/tokenized/train.pt` и `val.pt` скопированы из ДЗ 4 без изменений. Получить их можно из своего каталога `hw4/data/tokenized/`; исходные данные и пайплайн ДЗ 3–4 находятся в том же Git-репозитории. `scripts/prepare_eval.py` проверяет повторное кодирование всех train-примеров; SHA256 и результат проверки записаны в `docs/conclusion.md`. Полный индекс содержит 1222 исходных вопроса, а не только пул из 32 вопросов короткого sweep.

Проверочные JSONL закреплены в `dvc.yaml`/`dvc.lock`. Для восстановления с этой машины: `../hw3/.venv/bin/dvc pull`. Локальный remote — `hw67/dvc_remote`, он не включается в Git. Для сдачи отдельно приложить проверочные JSONL из `data/eval/` и обязательные отчёты из `metrics/`, без train-тензоров. Для DVC на другой машине установить DVC 3.67.1 (`uv tool install dvc==3.67.1`) и использовать обычный `dvc pull`; после распаковки данных можно выполнить `dvc commit` для наполнения локального кеша.

Заново сформировать golden/index и проверить связь с HW4: `uv run python scripts/prepare_eval.py` или `dvc repro`. Полная проверка тензоров использует прежний код из соседних `hw3/` и `hw4/`; эти каталоги должны быть из того же коммита репозитория.

Golden составлен по пяти отложенным темам; ссылки на официальные Android/Firebase источники записаны в каждой строке. `review` явно указывает проверку агентом. Перед сдачей человек должен прочитать вопросы и разметку; это не объявляется уже выполненной человеческой проверкой. Связанный перефраз и форматный кейс не прибавляются к n=50.

## Проверки

- `make check-all`: девять реальных проверок MLflow и 24 исходных unit/integration теста.
- Исходный отпечаток всех файлов `tests/`: **c42ac7788026**, совпадает с заданием.

MLflow: http://127.0.0.1:5006. `make down` сохраняет volumes. Не применять `down -v`: это уничтожит хранилища.
Пути `metrics/`, `.venv/`, тензоры, веса и Docker volumes исключены из Git; отчёты и JSONL оценки сохраняются отдельно в комплекте сдачи.

На этой машине успешный sweep потребовал лимиты MPS `PYTORCH_MPS_HIGH_WATERMARK_RATIO=0.7` и `PYTORCH_MPS_LOW_WATERMARK_RATIO=0.5`; первый sweep с лимитом 0.5 остановился с OOM и сохранён в MLflow. Перед `make sweep` экспортировать эти два значения. Список завершённых кандидатов находится в `metrics/sweep.json`; не выбирать все runs эксперимента без привязки к его parent_id.

Фактический итог: кандидат отклонён; `make eval` штатно возвращает ненулевой код. Не запускать `make promote` или `baseline-update` для этого кандидата.
