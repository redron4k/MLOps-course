# ДЗ 5 — LoRA на собственном датасете Android-разработки

Исправленный цикл обучения Qwen3-0.6B на тензорах собственной ДЗ 4:
1221 пример train и 162 примера val, длина до 2048 токенов.
Два эксперимента — LoRA на всех 28 слоях и только на слоях 14–27.
Разбор пяти исходных дефектов и измерения: [docs/defects.md](docs/defects.md).

## Подготовка и запуск

Нужны Python 3.12+, uv и свои обычные `train.pt`, `val.pt` из стадии
`tokenize` ДЗ 4. Положите их в `data/tokenized/`; упакованные
`train_packed.pt` и `val_packed.pt` здесь не используются.
При первом запуске нужен доступ к Hugging Face для базовой модели.

```bash
uv sync --locked
make train        # оба варианта и docs/curves.png
make compare      # база против all_layers на пяти Android-вопросах
make check        # девять проверок
```

После загрузки базовых весов можно запускать без сети:

```bash
HF_HUB_OFFLINE=1 make train
HF_HUB_OFFLINE=1 make compare
HF_HUB_OFFLINE=1 make check
```

Для пробного запуска без замены финальных артефактов:

```bash
uv run python -m src.train --variant all_layers --max-steps 3 --val-limit 8 --out /tmp/hw5-smoke
```

## Конфигурация и ресурсы

`params.yaml` задаёт модель, устройство, данные, LoRA, обучение и промпты.
Используются r=8, alpha=16, lr=2e-4, одна эпоха, seed=42.
Микробатч 1 × накопление 8 = эффективный батч 8; eval_batch_size=1,
gradient checkpointing включён. Для CPU задайте dtype=float32;
полный запуск на CPU существенно медленнее.

На машине с 24 ГиБ памяти используется MPS и bfloat16. По умолчанию
лимит MPS равен 0.8 рекомендованного рабочего объёма: исходные 0.5 и 0.7
не вмещали длинный пример. Лимит можно переопределить переменной
`PYTORCH_MPS_HIGH_WATERMARK_RATIO`; он не отключается.

Время в метриках — чистое обучение без загрузки, сохранения и оценки.
Валидация выполняется до обучения, каждые 10 шагов и на последнем шаге.
Последняя неполная группа накопления также обрабатывается.

## Артефакты и приёмка

- `docs/curves.png` — train/val обоих вариантов.
- `docs/compare.md` — пять фиксированных вопросов, ответы базы и адаптера.
- `docs/defects.md` — причины, исправления и числа собственного прогона.
- `docs/check.log` — фактический вывод `make check`.
- `docs/check.mp4` — запись этого вывода с сокращёнными паузами.
- `models/adapter_*` — матрицы LoRA, конфигурация и токенизатор с чат-шаблоном.
- `metrics/*.json` — кривые и метрики; пересоздаются командами выше.

Стадии `train_all`, `train_freeze`, `compare` описаны в `dvc.yaml`.
После правок кода обучения или его конфигурации перезапустите `make train`,
затем `make compare`: проверка сверяет свежесть артефактов.
Проверочный `tests/check.sh` не менялся, отпечаток — `06a02208c1f0`.
Его офлайн-проверка использует копию папки адаптера и базовые веса из HF-кеша.

В git сохраняются код, uv.lock, конфигурация и отчётные файлы `docs/`.
Данные, модели, JSON-метрики и `.venv` исключены через `.gitignore`.
`make clean` удаляет результаты обучения; `make distclean` также удаляет окружение.
