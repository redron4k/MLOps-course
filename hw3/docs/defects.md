# Разбор дефектов шаблона

## 1. Данные попадали в git

**Проявление.** В исходном `.gitignore` не было `data/`; команда `git add .`
могла добавить большие JSONL в историю.

**Исправление.** Добавлен `data/` в `.gitignore`; сырые, очищенные и разделённые
JSONL объявлены выходами DVC. Настроен локальный remote `dvc_remote/`.

**Подтверждение.** Первая часть `make check` показывает **0** отслеживаемых
git-файлов в `data/` и наличие всех **5** JSONL-артефактов в `dvc.yaml`.

## 2. Смена версии не пересчитывала результаты

**Проявление.** В `clean.deps` отсутствовал `data/raw.jsonl`. После изменения
`collect.version` DVC восстанавливал новый сырой файл, а `clean.jsonl` оставался
от прежней версии: хэш был одинаковым `a1002ee5`.

**Исправление.** `collect` зависит от секции `collect` в `params.yaml`, а
`clean` — от `data/raw.jsonl` и кода обработки. Добавлены использованные пути
и `src/stats.py` в зависимости стадий.

**Подтверждение.** Четвёртая часть `make check`: хэш очищенного файла меняется
с `06dfbf1f` (`v1`, **1500** сырых строк) на `cbfbc6d5` (`v2`, **1777**).
После очистки остаются **1315** и **1546** строк соответственно.

## 3. В train и test попадали связанные примеры

**Проявление.** Исходный `row_split` перемешивал отдельные строки, хотя
несколько вопросов могли иметь один `topic`.

**Исправление.** `group_split` распределяет целые группы по одному сплиту.
После разбиения `split` вызывает проверку контаминации и останавливается при
любом пересечении; та же проверка доступна отдельной командой.

**Подтверждение.** Для `v1` train/test имеют **0** общих ID, текстов, групп и
близких пар. Размеры train/val/test — **1055/139/121**; для `v2` —
**1222/162/162**.

## 4. Близкий дубль переживал очистку

**Проявление.** Шаг near-duplicate был пустым, поэтому разная пунктуация и
перестановка вариантов не удалялись точной дедупликацией.

**Исправление.** После точной дедупликации запускается MinHash/LSH по
нормализованному вопросу с порогом **0,85**.

**Подтверждение.** Вторая часть `make check` подставляет контрольные примеры:
удаляются **1 точный** и **1 близкий** дубль. В реальном срезе `v1` счётчики
дублей — **0/0**; это измеренный результат, а не отключённая стадия.

## 5. Вырожденный набор проходил проверку

**Проявление.** `diversity` только печатал предупреждение и завершался с кодом
0 даже при нарушенных порогах.

**Исправление.** Стадия выводит каждое нарушение и завершается с кодом 1.

**Подтверждение.** Шестая часть `make check` отклоняет синтетический набор из
**1200** строк и называет **4** нарушенных порога. Реальный `v2` проходит:
**1546** строк, **3** системных промпта, **50** групп, крупнейшая — **2,65%**
при допустимых 10%.

## 6. Группы были почти уникальными

**Проявление.** Группа строилась из комбинации тегов конкретного вопроса. В
предыдущем `v2` получилось **1322** группы на **2099** строк, из них **1157**
групп содержали по одному примеру. Такой ключ почти совпадал с ID и не давал
содержательного группового сплита.

**Исправление.** В `params.yaml` задана фиксированная таксономия из 50
Android-тематик. Сборщик назначает тему по запросу, а `diversity` дополнительно
проверяет минимальный размер группы и долю одиночных групп.

**Подтверждение.** В `v1` после очистки 50 групп с минимумом **18** и медианой
**27** строк; в `v2` минимум **25**, медиана **30**. Одиночных групп нет.
