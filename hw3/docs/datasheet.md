# Паспорт датасета: Android troubleshooting Q&A

## Назначение и состав

Датасет предназначен для учебного дообучения ассистента, который отвечает на
вопросы разработчиков Android-приложений. Одна строка JSONL содержит `id`,
`topic` и три сообщения в порядке `system → user → assistant`. Вопрос пользователя
состоит из заголовка и текста публикации; ответ ассистента — принятый автором
вопроса ответ Stack Overflow. Три системные инструкции назначаются
детерминированно по ID вопроса.

## Источник, сбор и права

Первичные записи получены собственным сборщиком `src/collect.py` через
[Stack Exchange API v2.3](https://api.stackexchange.com/docs), методом
`/search/advanced` и запросами принятых ответов. Сайт — Stack Overflow.
Критерии сбора: одна из 50 Android-тематик, открытый вопрос, принятый ответ и
период публикации из `params.yaml`. Каждая тематика задана отдельным запросом
по одному или нескольким тегам. Сборщик удаляет повторные ID, преобразует HTML
в текст и формирует собственный chat-формат. Локальный кэш HTTP-ответов и
готовых записей позволяет продолжить сбор после ограничения API; сигнатура
кэша включает окна, таксономию и системные промпты. Исходную публикацию строки
можно найти по `id = so-<question_id>` на
`https://stackoverflow.com/questions/<question_id>`; страница содержит автора
вопроса и ответа.

Публикации после 2 мая 2018 года предоставлены под
[CC BY-SA 4.0](https://stackoverflow.com/help/licensing). При дальнейшем
распространении производного датасета необходимо сохранять указание авторов,
ссылки на публикации, лицензию и условия ShareAlike. В git входят код, DVC lock
и метрики; тексты вопросов и ответов хранятся через DVC.

## Обработка

`collect` формирует сырые записи; `clean` сначала валидирует схему, затем
отбрасывает вопросы вне диапазона 30–4000 символов и ответы короче 2 символов,
маскирует найденные телефоны, email и даты рождения, удаляет точные и близкие
повторы вопросов. Ошибка JSONL или схемы останавливает обработку с номером
строки. `diversity` проверяет набор целиком, затем `split` раздаёт целые группы
по train/val/test. Группа — одна из 50 заранее заданных Android-тематик:
например, `ui-compose`, `room`, `workmanager`, `coroutines` или `camerax`.
Один и тот же ID закрепляется за первой подходящей тематикой. Между train и
test проверяются ID, текст, группы и близкие пары.

В `v1` длина вопроса: медиана 1180, p90 2773, p99 3880 символов; длина
ответа: медиана 556, p90 1592, p99 5210 символов. Для `v2` соответствующие
медианы равны 1173 и 553 символам. Доля крупнейшей группы составляет 2,28% в
`v1` и 2,65% в `v2`; используются три системных промпта, дословно
повторяющихся ответов нет. В `v2` найдено 29 вхождений email в 18 строках;
они замаскированы. Очистка реального среза не нашла повторов, а контрольные
примеры подтверждают удаление одного точного и одного близкого дубликата.
Порог близости при очистке и контроле утечки одинаков: 0,85.

Сплит детерминированный с seed 42 и целевыми долями 80/10/10. Для `v1`
фактические доли 80,23/10,57/9,20%, для `v2` — 79,04/10,48/10,48%.
Пересечений train/test по ID, тексту, группе и близким парам — по нулю в обеих
версиях.

## Ограничения

- Принятый ответ — сигнал от автора вопроса, а не независимая техническая
  экспертиза. Советы могут устареть при изменении Android API и библиотек.
- Англоязычные публикации преобладают; корпус не является русскоязычным.
- Фиксированная таксономия делает группы пригодными для сплита, но вопрос на
  стыке нескольких подсистем получает только первую подходящую тему.
- Преобразование HTML в текст сохраняет содержимое кода, но не гарантирует
  исходные отступы в многострочных фрагментах. Для задачи генерации кода
  понадобится отдельный парсер блоков `<pre><code>`.
- Автоматическая маскировка ПДн покрывает только телефон, email и дату рождения
  с явным маркером. Перед публикацией нужен ручной просмотр выборки.
- Нулевое пересечение по MinHash не доказывает отсутствие сложных смысловых
  перефразов; перед публикацией нужна дополнительная ручная проверка.
