# ДЗ 3 — Свой датасет + DVC: версии, валидация схемы, честный сплит

## Что нужно сделать

1. Поднять окружение: `uv sync`, закоммитить `uv.lock`.
2. Стадия `collect` собирает **свой** датасет по теме «Диагностика проблем
   Android-разработки на Kotlin, Jetpack Compose и AndroidX» из открытого
   Stack Exchange API. Она получает вопросы с принятыми ответами и формирует
   JSONL со строками `{"id", "topic", "messages": [system, user, assistant]}`.
   В `params.yaml` находятся теги, период выгрузки и две версии датасета.
3. Переисполнить пайплайн и проверить, что после очистки остаётся ≥ 1000
   примеров, а гейты разнообразия и контаминации проходят.
4. Описать в `docs/defects.md` пять исправленных дефектов и их проверки.
5. Сделать две версии датасета — v1 и расширенную v2 — и показать разницу
   через `dvc metrics diff`.
6. Написать `docs/datasheet.md`: источник, лицензия, объём, распределение
   длин, известные ограничения.
7. Написать `docs/defects.md`: **разбор каждого найденного дефекта** — в чём
   был, как проявлялся, как исправлен. Простое «починил» не засчитывается.

## Симптомы пяти дефектов

- После `git add . && git commit` в истории git оказываются файлы датасета:
  `git log --stat` показывает крупные JSONL. Так версионировать данные нельзя.
- Меняете версию данных в `params.yaml`, запускаете `dvc repro` — и он
  сообщает, что пересчитывать нечего. Артефакты остались от прошлой версии.
- Скрипт проверки контаминации находит пересечения между train и test:
  один и тот же вопрос (или его парафраз) попал в оба сплита.
- Пара почти одинаковых примеров — тот же вопрос, переставленные варианты
  ответа — переживает очистку и остаётся в датасете дважды.
- Подсовываете стадии заведомо вырожденный набор — тысяча строк с одним
  системным промптом, одной темой и ответами одной длины, — а пайплайн
  проходит целиком и ничего не сообщает. Проверка 6 при этом красная.

## Запуск

```bash
uv sync
make repro             # весь пайплайн
make v1 / make v2      # переключение версии датасета
make diff              # dvc metrics diff
make diversity         # гейт разнообразия
make contamination     # гейт train/test
make check             # самопроверка — должна стать зелёной
```

## Подсказка

`make check` устроен так, что каждый дефект валит хотя бы одну проверку.
Начните с неё: она называет симптом, но не место.

Данные в git попадать не должны ни при каких обстоятельствах — ни сейчас,
ни на девятой неделе, когда репозиторий соберёт CI.
